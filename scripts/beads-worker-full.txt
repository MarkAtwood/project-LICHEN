# Beads Worker

This project uses `bd` (beads) for task tracking. All work comes from beads.
Do NOT use TodoWrite, TaskCreate, or markdown TODOs — only `bd`.

## Loop

1. Get next: `bd ready | head -1` → `bd update <id> --claim`
2. Read: `bd show <id>`
3. Fix, run tests
4. Codereview 3x on files you touched (correctness / security / edge) —
   DO NOT review with your own model. Delegate each pass to the reviewer:
   `opencode run --agent plan -m openrouter/moonshotai/kimi-k3 "Code review pass <correctness|security|edge-cases> on <touched files>. Read the changes, report only real defects with file:line. Answer with PASS or a numbered findings list."`
   - Reviewer is read-only (`plan` agent); it never edits files.
   - If the bead touches crypto/security/concurrency (`lichen-oscore`, `schnorr`,
     `rpl`, keys, handshake, replay) use `-m anthropic/claude-opus-4-5` instead.
   - If `opencode run` fails (no API access, timeout), do the pass yourself and note it in the close reason.
   - Findings → `bd create` (new beads), not recursive fixes
5. Close: `bd close <id>`
6. Commit: `git add <changed files> && git commit -m "fix(<area>): <what>"`
   - NEVER stage `.beads/` — bd writes the shared store directly via BEADS_DIR.
7. Repeat until `bd ready` empty

## Skip if

- `blocked:hardware` label — needs physical bench hardware
- `needs-linux` label — work it via `ssh heft` (local Linux builder); EC2 only if heft lacks the toolchain
- Too complex (>50 lines needed) — decompose with `bd create`, close parent, pick next
- Stuck >5 min — release and move on

## Dirty file check (after claiming bead)

After `bd show <id>`, identify target files from the bead description/tags.
Run `git status --short` on those paths. If any show uncommitted changes you
didn't make, release the bead and pick another — that file is mid-edit by
another agent. Unrelated dirty files in other subsystems are fine to ignore.

`bd ready` already filters deferred and dependency-blocked beads.
Beads commands run against the shared store via BEADS_DIR — do not
create, move, or stage anything under `.beads/` yourself.

## Rules

- ONE bead at a time. Finish or release before next.
- Release: `bd update <id> --status open --assignee ""`
- Never use /tmp — use /Volumes/Attic/tmp/
