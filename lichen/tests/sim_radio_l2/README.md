# Simulator-radio native_sim integration probe

Status: **signed C/Python roundtrip passed on Zephyr 4.1.0 native_sim/native/64**.
Zephyr's existing NSOS backend connects the real `lora_sim` driver to host
TCP. No custom TCP bridge is needed.

The permanent `run.py` starts the existing `Simulation` in REALTIME mode
and `NodeServer`, connects a Python `SimRadio`/`LinkLayer` peer, then launches
the C executable with `-rt`. The C node is at (0, 0, 0), the Python peer at
(1, 0, 0). Both provision fixed test identities; counters and signatures
are generated by the actual link implementations.

The C test sends a separately constructed IPv6/UDP packet through
production LICHEN L2. Python authenticates the C Schnorr48 signature and
compares the decoded packet to its own packet/checksum construction.
Python then sends a **newly signed, distinct response**, and C checks native
UDP socket delivery plus exact reconstructed IPv6 packet bytes and real
L2 counters. The runner fails on authentication errors, packet mismatches,
nonzero C exit, or its 30-second deadline.

This deliberately tests SCHC **Rule 255 full-IPv6 fallback**, not Rule 0
compression: no peer DIO/rule negotiation is established. Python uses its
standalone Rule 255 codec after real LinkLayer authentication; it does not
forge Node-level authenticated context/receipt tokens. It is a two-peer
L2/codec transport test, not proof of Node/RPL admission policy, CoAP
application behavior, OSCORE, fragmentation, or A–B–C relaying.

## Required host-socket configuration

See `prj.conf` and `app.overlay`. The essential NSOS settings are:

```ini
CONFIG_NETWORKING=y
CONFIG_NET_DRIVERS=y
CONFIG_NET_SOCKETS=y
CONFIG_ZVFS_OPEN_MAX=8
CONFIG_NET_SOCKETS_OFFLOAD=y
CONFIG_NET_NATIVE_OFFLOADED_SOCKETS=y
CONFIG_NET_SOCKETS_OFFLOAD_DISPATCHER=y
CONFIG_NET_INTERFACE_NAME=y
CONFIG_HEAP_MEM_POOL_SIZE=16384
CONFIG_ETH_NATIVE_POSIX=n
```

Keep `CONFIG_POSIX_API` disabled: enabling it caused conflicting host and
Zephyr pthread types in `nsos_sockets.c` on this Zephyr 4.1/native_sim setup.
`NET_NATIVE` remains enabled for mesh traffic. The TCP driver can use
AF_INET through NSOS even with `CONFIG_NET_IPV4=n` and `CONFIG_NET_TCP=n`.
Start the medium before the executable: the driver connects at device init.
Use native_sim `-rt` for host-backed, wall-clock medium exchanges.

NSOS priority 40 precedes native socket priority 50. Therefore ordinary
application sockets also default to the host. This test enables
`NET_SOCKETS_OFFLOAD_DISPATCHER` and selects the LICHEN interface with
`SO_BINDTODEVICE` **before any other operation on the UDP socket**, using
the name returned by `net_if_get_name()`. Eight VFS descriptors accommodate
console, simulator TCP, UDP, and the dispatcher's temporary descriptor;
the default four caused `ENFILE` during UDP socket dispatch.
Priorities alone cannot separate host TCP from mesh UDP: the native
provider's `inet_is_supported()` claims both IP families without filtering
protocols. A production runner must explicitly select mesh sockets or add
a separately reviewed driver-side selection/lifecycle change to preserve
native sockets as the default.

## Reproduction on heft

Run from the repository root. The Zephyr venv supplies build tooling;
`python/.venv` supplies the existing LICHEN Python dependencies (including
the pinned `lora-medium`). To prepare that Python environment if needed,
use `uv sync --project python --frozen`. No new dependency is required.
Port 4444 must be free. The runner starts the server before C device init.

```bash
export PATH=/home/mark/Developer/lichen-venv/bin:$PATH
export ZEPHYR_BASE=/home/mark/Developer/lichen-workspace/zephyr
export ZEPHYR_SDK_INSTALL_DIR=/home/mark/Developer/zephyr-sdk/zephyr-sdk-0.16.8
cmake -GNinja -DBOARD=native_sim/native/64 \
  '-DZEPHYR_MODULES=/home/mark/Developer/lichen-workspace/project-LICHEN/lichen;/home/mark/GIT/zcbor;/home/mark/Developer/lichen-workspace/modules/crypto/tinycrypt;/home/mark/Developer/lichen-workspace/modules/crypto/mbedtls' \
  -S lichen/tests/sim_radio_l2 -B /tmp/opencode/oa51-c-medium/build
cmake --build /tmp/opencode/oa51-c-medium/build
python/.venv/bin/python lichen/tests/sim_radio_l2/run.py \
  /tmp/opencode/oa51-c-medium/build/zephyr/zephyr.exe
```

For another port, pass `-DCONFIG_LORA_LICHEN_SIM_PORT=<port>` at CMake
configuration and `--port <port>` to `run.py`. Keep the default simulation
ID `lichen` and C node ID `node0`; Python registers as `python-peer`.

Expected output includes:

```text
Python authenticated C Schnorr48 frame and matched IPv6/UDP bytes
PASS - test_signed_tcp_roundtrip
PROJECT EXECUTION SUCCESSFUL
PASS: signed C/Python TCP-backed L2 roundtrip
```

The successful run reported C 1/1 passed and runner exit 0. Startup can
log `no signing key (-126)` for network-control TX attempted before the
test provisions its identity; the signed exchange occurs after provisioning.

## Prerequisite regression check (oa51.3.1)

The original optimized build failed `-Werror=null-dereference` because
SCHC tombstone/floor insertion dereferenced a potentially unresolved slot.
Explicit NULL guards now return `-ENOBUFS`, matching context allocation's
failed free-slot scan. Valid-state eviction and monotonicity policies are
unchanged. Existing host tests passed 14/14 with ASan and UBSan:

```bash
cmake -GNinja -S lichen/tests/schc_session_table \
  -B /tmp/opencode/oa51-c-medium/session-table-host
cmake --build /tmp/opencode/oa51-c-medium/session-table-host
ctest --test-dir /tmp/opencode/oa51-c-medium/session-table-host -V
```

Session logs live under `/tmp/opencode/oa51-c-medium/`:
`integration-build.log` and `roundtrip.log`. The old scratch `probe.py`
was only an initial host-connectivity experiment and is not used by this
test. All runner source needed for reproduction lives in this directory.
